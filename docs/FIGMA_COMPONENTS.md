# Figma Components

DesignSystem components are mirrored as Figma components in
[Jelly-Shark-DS](https://www.figma.com/design/Q8aV4lenWHPqPdwtoPKpvc/Jelly-Shark-DS). Code is
the source of truth; each Figma component is a projection of one Swift view. The variables they
bind to are documented in [FIGMA_TOKENS.md](FIGMA_TOKENS.md).

Each component's Figma description carries its Swift file, init signature, prop↔parameter
mapping, known deviations from code, and GitHub URL. It is the authoritative mapping until Code
Connect can show Swift snippets (see below).

## Building conventions

1. **Platform.** Size differences (type, spacing) come from the `Platform` variable mode, set on
   a frame. Structural differences get separate components prefixed `tvOS/` or `visionOS/`, as
   on ⮑ Input Fields. Avoid a Platform variant property: it doubles every set and can disagree
   with the frame's mode.
2. **Focus lift.** The component keeps its resting footprint; the scaled layer is centred inside
   it by auto layout and overflows, so focusing an instance never moves its neighbours — as on
   tvOS. Hanging labels are absolute children, so they never add width.
3. **Symbols in a fixed glyph box are SF Pro text,** as in Apple's own Figma kits: a text layer
   holding the symbol's character, bound to a text property. Copy as text in the SF Symbols
   app and paste it in; `figma.util.getSfSymbolCharacter(name)` gives the character in a
   script. Size and weight bind to the role's type variables and the fill follows the
   variants, with nothing to scale. Inline symbols, where SwiftUI spaces by the symbol's
   natural box, nest an 18pt `icon` instance instead.

   Scaled `icon` instances don't survive symbol swaps: a nested one keeps the component's
   width, and one in a slot misses its first swap and ignores the parent's variants.
   SF Pro doesn't render on Figma's servers, so MCP can't screenshot these glyphs or change
   them in an instance.
4. **Don't model what tvOS does for free.** Behaviour the system adds at runtime, such as a
   symbol growing with its focus platter, stays out of the design file rather than gaining a
   variable to imitate it. Note it as a deviation in the component description instead.
5. **Previews.** Each component gets a `Theme Modes — <name>` frame: one column per theme,
   each with an explicit `Theme` mode on a `color/background` ground.
6. **Structure.** `ArtworkShelfItem`'s artwork and caption lines are flat siblings of the button
   label — the tvOS borderless focus lockup breaks if they're wrapped in a stack.

## Liquid Glass calibration

Figma's glass effect is tuned by measurement, not by eye. Resting glass is compared against a
`#Preview` render; focused glass against a tvOS simulator capture (previews never show focus).

1. Export a backdrop from the file (an `ArtworkImage` example) with `get_screenshot`.
2. Draw the real component over it in a scratch `#Preview`
   (`UIImage(contentsOfFile:)` on a host path works) and render it; for focus, capture the
   simulator with the `sim-ui-check` skill.
3. Put Figma instances at the same spots and compare crops side by side.
4. Sample pixels **raw** (`NSBitmapImageRep.getPixel`). `get_screenshot` URL PNGs carry no
   colour profile while preview and simulator PNGs are tagged sRGB; converting them reads
   different values for the same colour.

Current values on `tvOS/CircleActionButton` (calibrated 2026-10-30, preview and simulator,
not device):

| State | Figma treatment | Match |
|---|---|---|
| Resting | Glass: frost 3, refraction 1.0, depth 38, light 0.2 at −45°, dispersion 0.3; 8% white fill | Flat ground: #232426 vs code #252528; over artwork the edge lens matches |
| Focused, themed | `color/focusFill` + 5% white lift, same glass; 1.05× | Horror: #63112E vs code #681131 |
| Focused, Standard | White `systemPlatter` at 82%; 82.7pt (`focus/platter-padding`) | Lightness matches; real system glass also tints toward the backdrop, which isn't modelled |

Paint opacity is lost when a fill is bound to a variable, so partial-alpha white is a raw paint.

## Code Connect

1. **What works on the Professional plan.** Mappings made in the Figma app (Dev Mode →
   Connect to code, through the GitHub app link) attach a Swift file to a component.
   `ArtworkImage` and `ArtworkShelfItem` are mapped this way. These show the file and component
   name only — no snippet.
2. **What doesn't.** Mappings can't be written over MCP (`add_code_connect_map` refuses: "only
   … Organization or Enterprise plans"), and templates — the only way to get a real
   `CircleActionButton(…)` snippet — need the same plans. `tvOS/CircleActionButton` is not
   mapped yet; map it in the app.
3. **Reading** mappings over MCP (`get_code_connect_map`) works.

## Dev Mode annotations

Annotations are the second mapping channel, and unlike descriptions they attach to any node.
`node.annotations` reads and writes them over MCP; `labelMarkdown` renders bold and code ticks
in Dev Mode. Use them for per-node notes a description can't hold — which variable a fill
resolves through, why a frame carries an explicit `Theme` mode, where a calibrated value came
from.
